# Guidance: Authentication credentials never appear in logs

Log user identifiers (user ID, account ID) rather than authentication material. Identifiers are stable, useful for correlation, and not credentials. When logging authentication events (login success, login failure, password change), log the event type and user identifier, not the credential. Log success and failure equivalently to avoid creating timing inferences from log content. When a credential must appear in log context for debugging, use a redaction or masking function: log the first few characters of a token (a fingerprint) rather than the full value. Hash digests are acceptable when the value is sensitive enough that even a prefix is risky. Configure logging filters to catch common credential names (password, token, api_key, secret, authorization, cookie) in structured log payloads. The filter redacts these fields automatically. Configure exception handling to redact credentials before stack traces are logged. Library exceptions sometimes include request data in their messages.
