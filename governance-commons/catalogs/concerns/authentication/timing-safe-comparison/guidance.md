# Guidance: Credential comparison uses a timing-safe equality function

Python: hmac.compare_digest from the standard library hmac module. Works on bytes or str inputs of equal length. JavaScript and Node.js: crypto.timingSafeEqual from the Node crypto module. Requires Buffer inputs of equal length. Java: MessageDigest.isEqual from java.security. Works on byte arrays. Go: subtle.ConstantTimeCompare from crypto/subtle. Works on byte slices; returns int rather than bool to discourage non-constant-time callers from short-circuiting on the result. C and C++: bcmp, CRYPTO_memcmp from OpenSSL, or similar. memcmp is not constant-time and is disallowed for credential comparison. .NET: CryptographicOperations.FixedTimeEquals from System.Security.Cryptography. Ruby: Rack::Utils.secure_compare from Rack, or OpenSSL::Random equivalents. Most password hashing libraries (bcrypt, Argon2, scrypt verify functions) perform constant-time comparison internally. Code that calls library.verify(hash, password) is already timing-safe for that comparison; the rule applies when comparing other credential material that doesn't flow through a password verification library.
