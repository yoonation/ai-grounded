# Guidance: Authentication credentials never appear in URLs

For HTTP-based authentication, credentials are transmitted in one of the following ways: Authorization header: standard pattern for tokens. Bearer scheme for opaque tokens and JWTs: 'Authorization: Bearer <token>'. Basic scheme for username and password (only over TLS; deprecated for user authentication, acceptable for service-to-service in some contexts). POST request body: for credentials submitted during login (username and password in JSON body or form-encoded body). Never in query string. HttpOnly Secure cookies: for session tokens that browsers should attach automatically. SameSite=Lax or SameSite=Strict for CSRF protection. Custom headers: acceptable for API keys ('X-API-Key: <key>'). Standard headers like Authorization are preferred when applicable. OAuth 2.0 authorization code flow: the authorization code itself appears in the redirect URI by RFC 6749 design. This is the protocol-defined exception. The code is short-lived (typically 60 seconds) and single-use, mitigating leak exposure. OAuth tokens (access, refresh) never appear in URLs.
