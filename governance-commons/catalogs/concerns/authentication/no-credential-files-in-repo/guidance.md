# Guidance: Credential-bearing files are not committed to source repositories

Maintain a .gitignore (or equivalent) entry for each credential-bearing file pattern. Common entries: '.env', '.env.local', '.env.*.local', '*.pem', '*.key', '*.pfx', '*.p12', 'id_rsa*', 'aws-credentials', 'gcp-service-account.json'. Commit sample or template files with stable names that document the variables required. Convention: '.env.example', '.env.template', 'config.example.yaml'. These files contain variable names and dummy values ('DATABASE_PASSWORD=changeme'), making the contract explicit without leaking values. When credential files exist in the working tree during development, the .gitignore prevents accidental commit. Developers' shells refuse to stage them. For credentials that must be distributed (e.g., shared signing keys for a team), use encrypted form at rest: ansible-vault, SOPS, age, or git-crypt. The encrypted file is safe to commit because the decryption key is managed separately. Audit repository history for credential files that were committed before this rule was enforced. History rewrite (filter-branch, BFG Repo-Cleaner, git-filter-repo) removes them from history but does not remove them from existing clones. Treat any historically-committed credential as already compromised: rotate first, then clean history.
