# Guidance: Authentication tokens have an explicit expiration set at issuance

The substrate does not prescribe specific durations because they vary by application risk profile. The substrate-recommended starting points as of the substrate version cited above: Session tokens (interactive browser sessions): 8 to 24 hours, with idle timeout of 15 to 30 minutes. High-risk applications (banking, healthcare) prefer shorter values. JWT access tokens: 15 minutes to 1 hour. Short-lived by design; refresh-token flow extends the user's session without extending individual access tokens. JWT refresh tokens: 1 to 30 days. The refresh-token flow allows the access token to be short-lived without requiring the user to re-authenticate frequently. OAuth 2.0 access tokens: same as JWT access tokens (15 minutes to 1 hour). Password reset tokens: 15 minutes to 1 hour. Long enough to receive and click the email; short enough that delayed exploitation is bounded. Email verification tokens: 24 to 72 hours. Verifies the user controls the email; longer window accounts for users who delay reading their email. Magic link tokens: 15 minutes typical. These values are not normative. Consumers adjust based on application risk profile via profile tailoring.
